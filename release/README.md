# NEVERWIN — release

Готовые сборки: DLL. Правило версий простое: **чем больше число в
приписке `vN`, тем новее сборка**. Первая сборка — `v1`, следующая — `v2`,
и так далее. Старые версии не удаляются, лежат рядом для истории.

**С v79 инжекторы удалены из проекта** (исторические `*_injector_v*.exe`
удалены): DLL грузится любым внешним лоадером/инжектором
(`LoadLibraryW("...neverwin_vN.dll")` в cs2.exe).

## Что лежит

| Файл | Что это |
|---|---|
| `neverwin_vN.dll` | внутренняя DLL (x64 Release, статический рантайм, ImGui-меню) |
| `neverwin.ini` | оффсеты от последнего дампа (если сгенерирован) — DLL читает его при инжекте |

## Бинды

**P** — открыть/закрыть меню · F1 реверс аим (выкл → raimv1 → raimv2 → test) ·
F2 антиаимлесс (спинбот) · F3 visual recoil · F4 антибхоп · F5 gamesense ·
F6 Nonagon Ragebot · END — выгрузка.

Скорость спинбота F2 — слайдер 0..10 в меню: 0 — взгляд в пол без кручения,
1 — как раньше, 10 — в 10 раз быстрее. В Python-эдишн: F7/F8.

## Меню (v5+)

Меню рисует сама DLL **в игре**, по схеме quintcs2: хук на настоящем свопчейне
игры (сигнатура в rendersystemdx11.dll + MinHook), ImGui в бэкбуфер, мышь
освобождается хуком InputSystem::IsRelativeMouseMode. Открытие — **P** или
**INSERT**. Никаких dummy-свопчейнов, из-за которых крашились старые версии.



Если что-то не так: `%TEMP%\neverwin.log` — там видно, какой шаг меню
отвалился (свопчейн / MinHook / InputSystem / WndProc).

## Ragebot и автоогонь (v24+)

Проверка целей полностью переведена на цепочку
`CCSPlayerController -> m_hPlayerPawn -> pawn`. Цель проходит только при
согласованных `m_bPawnIsAlive`, health и lifeState; прямо перед выстрелом связь
с текущим pawn проверяется повторно. Dormant, spawn immunity, трупы и случайные
неигровые сущности больше не попадают в rage target list.

В меню Ragebot есть **«Автоогонь / триггер»**. Триггер ждёт pawn под прицелом
или остаточную ошибку не больше 1.5°, проверяет патроны, reload, запрет атаки и
weapon cooldown.

**v25 фикс камеры:** локальный `dwLocalPlayerPawn` больше не обязан проходить
controller-проверку целей. Устаревшие `m_hPlayerPawn`/`m_bPawnIsAlive` теперь
не выключают весь feature loop, поэтому F1/F2/visual recoil продолжают работать;
несовпадение controller-цепочки только пишется в лог.

Готовая сборка: `neverwin_v25.dll` + `neverwin_injector_v25.exe`.

## Реверс аим (v10+)

**F1** циклит: выкл → `raimv1` → `raimv2` → `test` → выкл (в меню — комбо).

- `raimv1` — прямая запись `dwViewAngles`;
- `raimv2` — запись в юзеркоманду (раскладка протобуфа решается рантайм-пробой,
  подстраховка прямой записью);
- `test` — канал как у андромеды: юзеркоманда (расширенная проба кандидатов
  quint/velocity/andromeda) + всегда страховка viewAngles. Если канал не
  встал — в логе `probe best N°`, по числу видно, насколько проба близка.

Обе версии: наводка на ближайшего **живого** тиммейта **через стены, без лимита
дальности**. Начиная с v24, здесь используется та же controller-based проверка,
что в Ragebot: одного `hp > 0` недостаточно, должны совпасть alive-флаг,
актуальный pawn handle и lifeState. Диагностика в `%TEMP%\neverwin.log` показывает
число controller/pawn/alive и причины отбрасывания цели.

`m_iTeamNum` читается как **uint8**, иначе соседние байты превращают номер команды
в мусор и ломают фильтр тиммейтов.

`neverwin.ini` общий для всех версий в этой папке: DLL ищет его рядом с собой.
Нет ini — DLL работает на встроенных оффсетах (и почти наверняка они стухшие,
если CS2 обновилась).

## Обновить оффсеты после патча Valve

1. Сними дамп: cs2-dumper с запущенной CS2 → папка `output/`.
2. Сгенерируй ini:
   ```
   python neverwin-internal/tools/dump_to_ini.py "C:\путь\к\output" "C:\папка с DLL\neverwin.ini"
   ```
3. Положи `neverwin.ini` в эту папку (рядом с DLL). Пересобирать DLL не нужно.
   Хочешь обновить и встроенные оффсеты в коде — `neverwin-internal/src/offsets.hpp`.

## Сборка релиза

- **Windows (VS2022):** `release\build_release.bat` — или `build_release.bat 3` для явной версии 3.
- **Linux (кросс, zig):** `bash release/build_release.sh` — версия автоинкрементится.

Обе сборки кладут результат сюда с правильной припиской `vN`.
